---

### 1. Summary  
At 14:32 UTC the `checkout-service` began experiencing 30 s database connection timeouts. Concurrently, host metrics showed memory usage at ~95 %, GC pause times exceeding 200 ms, and disk I/O throughput dropping below 10 % of capacity. The issue resolved after the host was rebooted and the JVM heap was reduced, but the root cause analysis reveals that memory pressure was the primary driver.

---

### 2. Root Cause  
- **High memory usage (~95 %)** on the host caused severe memory pressure.  
- This triggered **frequent GC pauses** and **swapping** to disk.  
- The resulting **disk I/O slowdown** degraded database responsiveness.  
- The combination of GC pauses and slow I/O led to **database connection timeouts** in `checkout-service`.  
- **Primary factor:** memory pressure; **secondary factor:** disk I/O slowdown.

Confidence: **0.88** (high)

---

### 3. Recommended Fix  
1. **Add RAM** – increase host memory from 32 GB to 64 GB.  
2. **Adjust JVM heap** – set `-Xmx4g` (well below the new limit) to reduce GC pressure.  
3. **Monitor** – verify that host memory usage stays < 70 % and GC pause times < 100 ms.  
4. **Validate** – run a load test to confirm database connection times return to < 5 s.

Confidence: **0.92** (very high)
